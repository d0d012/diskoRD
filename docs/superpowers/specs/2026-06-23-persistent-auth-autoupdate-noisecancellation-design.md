# Design: Persistent Auth, Auto-Updater, Noise Cancellation

**Date:** 2026-06-23
**Scope:** Tauri desktop app (frontend) + GitHub Actions CI

---

## 1. Persistent Auth

### Problem

Two bugs in `frontend/src/stores/authStore.ts`:
- Registration stores the access token in `sessionStorage` (wipes on app close)
- Both paths rely on the WebView's localStorage, which can be cleared on Tauri updates or OS-level WebView cache resets

### Solution

Add `tauri-plugin-store` (Tauri v2). Tokens are written to an encrypted file on disk (`~/.config/diskoRD/store.json`), surviving restarts, reinstalls, and WebView cache clears.

### Storage Abstraction

New file `frontend/src/lib/storage.ts` exposes a unified async API:

```ts
get(key: string): Promise<string | null>
set(key: string, value: string): Promise<void>
remove(key: string): Promise<void>
clear(): Promise<void>
```

- In Tauri context (`window.__TAURI__` defined): delegates to `@tauri-apps/plugin-store`
- In browser context: delegates to `localStorage`
- `sessionStorage` is removed entirely from auth flows

### Auth Store Changes (`authStore.ts`)

- `loadUser()` becomes async, reads from storage abstraction
- `login()`, `register()`, `logout()` use storage abstraction
- All `sessionStorage` references removed
- On app start: if refresh token exists in store, call `/api/auth/refresh` silently before rendering app shell. On success: store new access token, render app. On failure: clear store, show login.

### API Interceptor Changes (`api.ts`)

- Token refresh on 401 already works; ensure it writes new access token via storage abstraction (not raw `localStorage.setItem`)

### Tauri Changes

- Add `tauri-plugin-store` to `Cargo.toml`
- Register plugin in `src-tauri/src/lib.rs`
- No `tauri.conf.json` changes needed

### Backend

No changes.

## 2. Auto-Updater

### Architecture

```
Developer machine          GitHub                    Friends' machines
─────────────────          ──────                    ─────────────────
git tag v0.2.0      →   Actions builds EXE     ←  Tauri app checks on start
git push --tags     →   signs + uploads         →  downloads if newer
                        to GitHub Releases      →  installs on restart
```

### One-Time Setup

1. Generate keypair: `tauri signer generate -w ~/.tauri/private.key`
2. Public key → `tauri.conf.json` under `plugins.updater.pubkey`
3. Private key + password → GitHub Actions secrets (`TAURI_SIGNING_PRIVATE_KEY`, `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`)

### tauri.conf.json Changes

```json
{
  "plugins": {
    "updater": {
      "pubkey": "<generated-public-key>",
      "endpoints": ["https://github.com/d0d012/diskoRD/releases/latest/download/latest.json"]
    }
  }
}
```

### GitHub Actions Workflow

File: `.github/workflows/release.yml`

Triggers on: `push` to tags matching `v*`

Steps:
1. Checkout repo
2. Install Rust + Node
3. `npm install` in `frontend/`
4. `tauri build` with signing env vars set
5. Upload artifacts to GitHub Release (creates release automatically from tag)
6. Upload `latest.json` manifest (auto-generated by Tauri build) to the same release

Platforms: Windows first (friends use Windows). Mac/Linux can be added later by adding matrix targets.

### App Runtime Behavior

In `src-tauri/src/lib.rs`, on startup:
- Check for update via `tauri_plugin_updater`
- If update available: download in background, emit event to frontend
- Frontend shows a dismissible toast: "diskoRD v0.X.X is ready — restart to update"
- On restart: update installs automatically

### Cargo.toml Changes

Add: `tauri-plugin-updater = "2"`

## 3. Noise Cancellation

### Approach

RNNoise via WebAssembly. Open source, ~500KB bundle addition. Handles transient non-speech sounds (eating, typing, keyboard, fans) significantly better than browser-native `noiseSuppression`.

### Audio Pipeline

```
Microphone MediaStream
  → AudioContext.createMediaStreamSource()
  → AudioWorkletNode (RNNoise processor)
  → AudioContext.createMediaStreamDestination()
  → processed MediaStream
  → LiveKit Room.localParticipant.publishTrack(Track.createFromMediaStreamTrack(processedTrack))
```

### New Files

**`frontend/src/hooks/useNoiseCancellation.ts`**
- Loads RNNoise WASM module once (lazy, on first enable)
- Registers AudioWorklet processor
- Accepts raw `MediaStream`, returns processed `MediaStream`
- Exposes `{ enable, disable, isEnabled, isSupported }`

**`frontend/src/audio/rnnoise-processor.js`** (AudioWorklet)
- Runs in audio thread
- Buffers 480-sample frames (RNNoise requirement)
- Pipes frames through RNNoise, passes cleaned audio downstream

### Integration Points

**`frontend/src/hooks/useVoice.ts`**
- After acquiring local audio track, if noise cancellation is enabled, pipe through `useNoiseCancellation` before publishing to Room
- On toggle: unpublish current track, reprocess, republish

**`frontend/src/features/call/DMCallPanel.tsx`**
- Same pattern as `useVoice` — pipe mic stream through noise cancellation before passing to `new Room()`

**`frontend/src/features/voice/ControlBar.tsx`**
- Add noise cancellation toggle button (icon: waveform with slash when off)
- Shows "NC" indicator when active
- Calls `useNoiseCancellation().toggle()`

### Persistence

Noise cancellation preference stored via storage abstraction (`noiseCancellation: "true"|"false"`). Loaded on mount, applied before first mic publish.

### Dependencies

```
npm install rnnoise-wasm
```

**Vite config:** `rnnoise-wasm` ships a `.wasm` file. Add to `vite.config.ts`:
```ts
optimizeDeps: { exclude: ['rnnoise-wasm'] },
assetsInclude: ['**/*.wasm']
```

No backend changes. No LiveKit server changes.
